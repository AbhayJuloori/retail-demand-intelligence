# Retail Demand Intelligence — Design Spec
**Date:** 2026-05-19  
**Status:** Approved

---

## Overview

End-to-end retail demand forecasting + inventory optimization system with LLM-generated SKU insights. Targets supply chain data scientist roles (1-2 yr exp). Differentiators: ensemble ML + MLflow + SHAP explainability + provider-agnostic LLM layer + production deployment.

---

## Architecture

```
M5 Walmart Dataset
       ↓
[Data Pipeline] — preprocessing, feature engineering, train/val split
       ↓
[Forecasting Engine] — Prophet + LightGBM ensemble per SKU
       ↓
[Inventory Engine] — reorder point, safety stock, EOQ calculations
       ↓
[LLM Insight Layer] — Groq (Llama 3.3 70B) generates SKU narrative
       ↓
FastAPI (REST) ← serves forecasts, inventory status, LLM insights
       ↓
Next.js 15 Frontend — dashboard with charts, inventory table, insights panel
```

Three clean layers: ML pipeline (offline, precomputed nightly), API (serves results), Frontend (visualizes + shows LLM insights). No real-time inference — forecasts precomputed on demand trigger.

## Data Pipeline + Modeling

**Dataset:** M5 Walmart (Kaggle) — 30,490 SKUs across 10 stores, 5 years daily sales.

**Feature engineering:**
- Lag features: 7d, 14d, 28d
- Rolling means: 7d, 28d
- Day-of-week, month, week-of-year
- SNAP event flags (M5 includes these per state)
- Holiday/event calendar from M5 metadata

**Train/val split:** last 28 days held out. Rolling-window backtesting over last 90 days.

**Models:**
- Prophet per SKU — captures seasonality + holiday effects
- LightGBM — engineered features, cross-SKU pattern learning
- Ensemble: weighted average, weights tuned on val WRMSSE per SKU, fallback to Prophet on divergence

**Evaluation:** WRMSSE (M5 standard) + RMSE per SKU + model comparison table

**MLflow:** every training run logged (params, metrics, artifacts), best model promoted to registry

**SHAP:** LightGBM feature importance per SKU, surfaced in dashboard

**Output:** 28-day rolling forecast + uncertainty intervals (yhat_lower/yhat_upper) stored as parquet, refreshed on demand.

## Inventory Engine

**Formulas:**
- Reorder Point (ROP) = avg daily demand × lead time + safety stock
- Safety Stock = Z-score × std(forecast uncertainty) × √lead time — derived from Prophet uncertainty bounds, not hardcoded historical std
- EOQ = √(2 × demand × order cost / holding cost) — parameterized per SKU category

**Output per SKU:**
- Status: `OK` / `AT RISK` / `STOCKOUT IMMINENT`
- Days until stockout (given 28d forecast)
- Recommended order quantity + trigger date

**Lead time assumption:** default 7 days, configurable per SKU category via `config/inventory_params.json`.

**Note:** M5 lacks inventory levels — synthetic starting inventory seeded from historical sales patterns. Disclosed in README.

## LLM Insight Layer

**Provider-agnostic design:** single `llm_client.py` abstraction, swap providers via `LLM_PROVIDER` env var.

**Supported providers:**
- `groq` — default demo (Llama 3.3 70B, free tier, 14,400 req/day)
- `openai` — GPT-4o mini
- `anthropic` — Claude Haiku
- `gemini` — Gemini Flash (Google free tier)

**Demo deployment:** Groq free tier via Railway env var — no API key in code or repo.

**Cloners — two paths:**
1. `.env` file: set `GROQ_API_KEY` / `OPENAI_API_KEY` / `ANTHROPIC_API_KEY` / `GEMINI_API_KEY`
2. "Bring Your Own Key" modal in frontend — key stored in browser `localStorage` only, sent as `X-LLM-Key` request header, never stored server-side. Backend validates key on first use and returns `401` with clear error if invalid. Disclaimer shown.

**Generation cadence:**
- Batch: pre-generated for top 100 at-risk SKUs via `POST /insights/refresh` endpoint (manual trigger on demo, no cron needed on free Railway tier), cached
- On-demand: "Generate Insight" button per SKU, live API call (~2s)

**Prompt structure:** system prompt cached (provider permitting), variable payload = forecast summary + inventory state + top 3 SHAP features + stockout risk score.

**Output format per SKU:**
```
Status: STOCKOUT RISK in 6 days
Trend: Demand up 18% vs 28-day avg, driven by SNAP event week + weekend spike
Recommendation: Order 340 units by Thursday. Safety stock margin 1.2 days — below 3-day threshold.
```

## Frontend (Next.js 15)

**Stack:** Next.js 15 App Router + shadcn/ui + Tailwind CSS + Recharts

**Visual style (inspired by organic/editorial design):**
- Light mode — cream/off-white base (`#F5F0EB`)
- Deep navy (`#1B2340`) for primary cards, chart fills, sidebar
- Muted pastels for status badges: sage green (OK), dusty lavender (AT RISK), dusty pink (STOCKOUT)
- Amber/gold accent for CTAs, critical alerts, standout KPI numbers
- Heavy border-radius on cards — soft, organic, not corporate
- Bold display font for KPI numbers (`font-black text-6xl`)
- Generous whitespace — data-dense but breathable

**4 Views:**

**1. Overview Dashboard**
- Top-bar KPIs: total SKUs monitored, % at risk, avg forecast accuracy (WRMSSE)
- Store heatmap by risk level
- Top 10 stockout alerts table with status badges + days-to-stockout

**2. SKU Explorer**
- Searchable/filterable table (store, category, risk status)
- Click SKU → side panel: 28d forecast chart (actual vs predicted + uncertainty band), inventory trajectory chart, SHAP top features bar chart

**3. Insights Feed**
- Pre-generated LLM narratives for top 100 at-risk SKUs
- Each card: status badge + narrative + recommended action + "Regenerate" button
- "Generate Insight" for any SKU not in top 100 (live Groq call)
- BYOK modal accessible from nav

**4. Model Performance**
- Backtesting WRMSSE/RMSE over rolling 90-day window
- Prophet vs LightGBM vs Ensemble comparison chart
- MLflow run history table (run ID, date, WRMSSE, model promoted Y/N)
